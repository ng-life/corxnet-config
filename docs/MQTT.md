# MQTT 配置读写协议与命令

本文根据用户提供的 CX-8308W 抓包和对应参数推测。MQTT 字段布局不是 `docs/20.docx` 明确记载的内容；设备型号或固件变化时，应先只读验证，不要直接套用写入。

## 抓包确认的帧格式

UDP 设备端口为 `60000`，本机端口为 `60001`，使用广播地址 `255.255.255.255`。帧中的 MAC 是完整 MAC 地址的 12 个 ASCII 十六进制字符（大写，无冒号）。

读取请求：

```text
33 BB + 12 字节 ASCII MAC + BB 33
```

读取响应以 `33 BB + MAC` 开始，以 `BB 33` 结束。

保存请求：

```text
44 AA + 12 字节 ASCII MAC + MQTT 参数区 + AA 44
```

抓包中保存帧与读取响应的参数区相同，UDP 负载长度为 623 字节。

## 参数区推测

参数区由五个固定宽度字段按以下顺序组成：

| 顺序 | 字段 | 样本值长度 | 长度字节 | 字段槽宽度 | 可用值长度 |
| --- | --- | ---: | --- | ---: | ---: |
| 1 | 用户名 | 68 | `44` | 101 字节 | 100 字节 |
| 2 | 密码 | 75 | `4B` | 101 字节 | 100 字节 |
| 3 | 订阅主题 | 24 | `18` | 101 字节 | 100 字节 |
| 4 | 发布主题 | 22 | `16` | 101 字节 | 100 字节 |
| 5 | 设备 ID | 15 | `0F` | 102 字节 | 101 字节 |

每个槽由一个二进制长度字节、对应长度的 ASCII 字节、以及补足槽宽的 `00` 组成。五个槽后有一个 `FF` 字节和 100 个 `00` 保留/填充字节，再接帧尾。槽宽和填充长度由这份抓包中的固定偏移推算；其中可用长度是格式推算值，不代表设备界面必然允许填满。

抓包确认了长度前缀、字段顺序和样本长度。用户名、密码内容本身不写入本仓库文档。

## 读取

```sh
corxnet-config -i br0 mqtt-read 00:90:E2:D7:20:60
```

必须提供完整 MAC。读取结果会明文显示全部 MQTT 字段，包括用户名和密码：

```sh
corxnet-config -i br0 mqtt-read 00:90:E2:D7:20:60
```

此命令只发送读取广播，不改动设备参数。

## 保存

`mqtt-set` 要求一次提供全部五个字段，避免未提供的字段被意外清空。用户名和密码通过参数明文指定：

```sh
corxnet-config -i br0 mqtt-set 00:90:E2:D7:20:60 \
  --username '<MQTT用户名>' \
  --password '<MQTT密码>' \
  --subscribe-topic 'SFQ257YC4K/WH-01/control' \
  --publish-topic 'SFQ257YC4K/WH-01/event' \
  --device-id 'SFQ257YC4KWH-01'
```

此命令先读取并在内存保留原值，再广播 `44 AA ... AA 44` 保存帧，随后复读核验五个字段。写前读取失败时不发送保存帧；写后复读失败或不一致时，尝试恢复写入前的五个原值并再次复读。失败退出时会说明恢复是否已确认；原值不会持久化，修改前仍需自行保留备份。读取输出及写入参数均为明文，终端日志、shell 历史或系统进程信息可能留存凭据；请勿将凭据写入仓库或公开日志。

## 修改前备份与恢复

写入会整体替换 MQTT 参数。先用读取命令记录当前五个字段（明文显示，需安全保管），再执行写入。若结果不符合预期，使用备份的五个原值运行 `mqtt-set` 恢复，并再次读取核验。不要把含凭据的终端输出、命令历史或备份文件提交到仓库。

常规回归测试使用 loopback UDP 模拟设备，覆盖写前读取失败不写入、写后核验、核验失败恢复及恢复失败提示，不访问真实控制器：

```sh
go test -race ./...
```

仓库不保留固定现场网卡或设备 MAC 的写入测试。真实设备测试需要另行授权，并先保留配置；若值发生变化，必须恢复并复读确认。

## 内嵌网页

`corxnet-config serve` 的 MQTT 页签使用上述相同报文编码。必须先点击“读取 MQTT 参数”；HTTP 服务在内存保留每台设备首次读取的五个原值，后续读取不覆盖恢复基线。整体保存前会再次读取，成功后才发送保存帧，随后自动复读核验全部五个字段。

若发送后复读失败或字段不一致，程序会尝试恢复本次写入前读取的原值并复读，页面会提示核验失败及恢复结果。可再次读取检查，或选择“恢复首次读取的原值”；恢复同样发送完整保存帧并复读核验。服务重启后原值丢失，需重新读取。凭据在页面明文显示，不写入浏览器存储或服务日志；HTTP 传输为明文，应仅在可信网络使用。
