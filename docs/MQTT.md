# MQTT 配置读写协议与命令

本文汇总用户提供的抓包分析、补充字段定义及用户反馈验证通过的 MQTT 读写格式，作为本项目 MQTT 协议依据。设备型号或固件变化时，应先只读验证。

## 帧格式

UDP 设备端口为 `60000`，本机端口为 `60001`，使用广播地址 `255.255.255.255`。寻址字段使用完整 MAC 去掉冒号后的 12 个大写 ASCII 十六进制字符，与内容区内可修改的“设备 ID”不同。

读取请求为 16 字节：

```text
33 BB + 12 字节 ASCII MAC + BB 33
```

读取响应为 623 字节：

```text
33 BB + 12 字节 ASCII MAC + 参数区 + BB 33
```

保存请求为 623 字节：

```text
44 AA + 12 字节 ASCII MAC + 参数区 + AA 44
```

读取响应与保存请求共用相同的参数区布局，帧头尾不同。读取时仅接受标识与目标 MAC 匹配的响应。

保存应答固定为 4 字节：

```text
44 AA AA 44
```

工具等待写前读取所确认的设备 UDP 地址发来保存应答，然后复读。应答超时后仍复读判断是否已生效；只有全部配置一致才报告成功。

## 内容区格式

读取响应与保存请求的内容区均为 607 字节：

```text
用户名长度(1) + 用户名(100)
+ 密码长度(1) + 密码(100)
+ 订阅主题长度(1) + 订阅主题(100)
+ 发布主题长度(1) + 发布主题(100)
+ 设备 ID 长度(1) + 设备 ID(100)
+ 心跳主题长度(1) + 心跳间隔秒数(1) + 心跳主题与内容(100)
```

括号内为字节数。长度字段是单字节二进制数，不是 ASCII 数字；前五个长度只计算各自有效内容，心跳主题长度只计算主题部分。六个内容区各固定为 100 字节，不足部分补 `00`。

## 完整帧偏移

偏移从整个 UDP 负载的第 `0` 字节开始：

| 偏移 | 字段 | 格式 |
| --- | --- | --- |
| `0–1` | 帧头 | 读取响应 `33 BB`；保存请求 `44 AA` |
| `2–13` | 寻址标识 | 12 字节 |
| `14`、`15–114` | 用户名长度、用户名 | 1 字节长度 + 100 字节内容区 |
| `115`、`116–215` | 密码长度、密码 | 1 字节长度 + 100 字节内容区 |
| `216`、`217–316` | 订阅主题长度、订阅主题 | 1 字节长度 + 100 字节内容区 |
| `317`、`318–417` | 发布主题长度、发布主题 | 1 字节长度 + 100 字节内容区 |
| `418`、`419–518` | 设备 ID 长度、设备 ID | 1 字节长度 + 100 字节内容区 |
| `519` | 心跳主题长度 | 1 字节，只计算主题长度 |
| `520` | 心跳间隔 | 1 字节，单位秒 |
| `521–620` | 心跳主题加内容 | 共用 100 字节内容区 |
| `621–622` | 帧尾 | 读取响应 `BB 33`；保存请求 `AA 44` |

完整帧总长度为 `2 + 12 + 607 + 2 = 623` 字节。偏移 `520` 是心跳间隔，不是固定 `FF` 标记；`521–620` 是心跳主题与内容，不是保留区。

工具把“心跳主题加内容”拆为心跳主题和心跳内容两个配置项。编码时直接拼接，不添加分隔符；解码时按主题长度拆分，去掉内容区末尾的零填充。主题和内容合计最多 100 字节。心跳间隔接受 `0–255` 秒；没有已确认的 `0` 特殊含义，工具不将其解释为关闭心跳。网络参数 `set ... heartbeat` 是另一个协议字段，不与 MQTT 心跳间隔互相转换。

工具当前沿用既有字符限制：文本只接受不含 NUL 的 ASCII，长度按字节计算。此限制是工具的支持范围，当前协议资料未明确字符编码。空文本和零间隔均可显式传入；不支持在心跳内容中嵌入二进制 NUL。

## 读取

```sh
corxnet-config -i br0 mqtt-read 00:90:E2:D7:20:60
```

必须提供完整 MAC。命令只读取，明文显示用户名、密码、订阅主题、发布主题、设备 ID、心跳主题、心跳内容和心跳间隔，不改动设备配置。

## 保存

`mqtt-set` 要求显式提供全部八个配置项，避免遗漏字段被清空：

```sh
corxnet-config -i br0 mqtt-set 00:90:E2:D7:20:60 \
  --username '<MQTT用户名>' \
  --password '<MQTT密码>' \
  --subscribe-topic 'example/device/control' \
  --publish-topic 'example/device/event' \
  --device-id 'example-device' \
  --heartbeat-topic 'example/device/heartbeat' \
  --heartbeat-content 'alive' \
  --heartbeat-interval 30
```

文本可以用 `--heartbeat-content ''` 等形式显式设为空。旧版仅提供五个字段的命令不再接受，HTTP 请求也必须提供全部八个字段。

命令先读取并在内存保留完整配置，再发送保存帧、等待应答并复读核验。写前读取失败时不写入；写后复读失败或不一致时，尝试恢复全部原值，包括心跳配置，并再次复读。失败退出时说明恢复是否已确认。

原值不会持久化。修改前应另行备份当前配置，以便进程退出后恢复。用户名和密码的输出及写入参数均为明文，终端日志、shell 历史或系统进程信息可能留存凭据；不要将真实凭据、备份或命令历史提交到仓库。

## 内嵌网页与 HTTP 接口

`corxnet-config serve` 的 MQTT 表单提供相同的八个配置项。必须先读取；HTTP 服务为每台设备在内存中保留首次读取的完整配置，后续读取不覆盖恢复基线。整体保存前再次读取，写后复读比对；“恢复首次读取的原值”也恢复心跳配置。重启服务会清除原值。

`POST /api/mqtt/set` 的 `config` 必须包含以下字段，间隔使用 JSON 整数，其余为字符串：

```json
{
  "username": "",
  "password": "",
  "subscribe_topic": "example/control",
  "publish_topic": "example/event",
  "device_id": "example-device",
  "heartbeat_topic": "example/heartbeat",
  "heartbeat_content": "alive",
  "heartbeat_interval": 30
}
```

凭据在页面明文显示，不写入浏览器存储或服务日志。HTTP 传输为明文，应仅在可信网络使用。

## 验证边界

```sh
go test -race ./...
```

用户已反馈本次修正验证通过；该反馈不代表全部型号和固件均兼容。

自动化测试使用独立按本文构造的响应样本及 loopback UDP 模拟设备，覆盖字段偏移、长度边界、读取筛选、应答、复读、心跳恢复、完整 JSON 与 CLI 参数，不访问真实控制器。离线测试不代表真实固件兼容性验证。

真实设备写入测试需要另行授权，并先备份完整配置；若发生变化，必须恢复并复读确认。不得使用未知命令探测设备。
